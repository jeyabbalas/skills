# schemify changelog

Changes to [`schemify`](../skills/schemify/SKILL.md), newest first. What major, minor, and patch mean: [README → Versions](../README.md#versions).

## 2.0.0 — 2026-10-13

- **Breaking:** schemify is rewritten. Work now lives in a `schemify/` workspace (state in an append-only ledger, the deliverable in `schemify/package/`), and the old `json_schema/` layout with PROGRESS.md, DECISIONS.md, SOURCES.md, and ROUTING.csv is retired. To move a 1.x package, run `/schemify` in the folder that holds it: the agent runs the new `migrate.py`, which converts schemas, decisions, rules, the inventory, and toy data into a new workspace and leaves your old folder untouched, then finishes the rest with you. `refresh-assets` alone does not upgrade a 1.x package.
- **Breaking:** the schemas follow a stricter house style. Every property and every skip-pattern rule carries `x-provenance` (where each fact came from: a source, a person's answer, or the agent's flagged guess), special codes carry `x-value-kind`, and every rule takes one canonical shape that downstream code can parse (`validate.py rules` prints them parsed). `migrate.py` adds what it can; the agent and `check` find the rest.
- **Breaking:** the playground page is gone. Checking real data now happens privately in [QuaC](https://jeyabbalas.github.io/quac/): the website walks you through it, and the agent receives only QuaC's findings without data — counts, never values.
- New project website, opened from the workspace: an overview of progress and what waits on you, batched questions with recommended answers ("not sure" applies the recommendation and flags it for your data steward), the data dictionary with a *Details* panel per variable showing where each part came from, a skip-logic view, every source and decision, and a data check: the toy data in an interactive table ([data-table](https://www.npmjs.com/package/@jeyabbalas/data-table) 0.10.0) with every validation error pinned to its cell and explained, then your real data checked privately in QuaC, with a history of how far your data and the schemas are apart. Answers go straight to the agent through a small local server, or as a downloaded file when the page is opened from disk.
- New: for public data, or an agent that runs on a model you control, you can let the agent check one named data file itself — say so in chat, or use *Let your agent run the check itself* on the Data check tab. It runs QuaC on the file whenever the schemas change (`schemify.py data-check`), fixes its own transcription slips, re-runs to confirm them, and asks you about everything else. It still reads only QuaC's findings without data, never the rows; a permission for your own model covers only that model, and *Stop* withdraws it.
- New: keep your real data checked automatically. On the Data check tab, *Connect QuaC* opens QuaC in its own tab, where you load your file once and press *Allow*; from then on, each time the agent changes the schemas it asks the website to have QuaC re-check, and only the findings without data come back — your data stays in QuaC, in your browser. Needs a QuaC with companion pages (the release after 1.2.0); until then, the check by hand works as before.
- New: an approval covers what you read, plus your answers to the questions you had been asked by then. When a topic's file changes otherwise after you approve it — a later answer, a comment, or a slip the agent fixed — it comes back to you, with the agent's note on what changed shown above it; a package that changes after it was finished is finished again.
- New: `check` warns when a variable rejects a special code its dictionary row lists, the slip that toy data alone cannot catch.
- New: the agent researches the study on the web (using findings only after you approve them), reads and digests your documents with subagents where your agent supports them, interviews you about your background, and extracts a data steward's knowledge topic by topic.
- New: contradictions between sources are always put to you; skip logic your documents do not state is inferred only with your consent and stays flagged for review.
- New: a review mode (`/schemify review`) for the data steward, who sees only the questions that need their knowledge, ranked and sized to the time they have.
- Sessions end with a written handoff whenever the agent hands work back to you, so a later session — or another agent — resumes exactly where this one stopped; the website and `START-HERE.md` say how to continue, including in Codex (`$schemify`) and when the website has to be opened from disk.
- New: `extract.py` turns Excel, CSV, PDF, Word, HTML, RTF, and cleaning code (SAS, Stata, R, SPSS, Python, SQL) into citable text and tables. It refuses data files, and a CSV or other delimited file until you have said it is documentation; it leaves out a workbook sheet that looks like participant records until you say it describes variables (`--include-sheet`), and blanks rows of data embedded in code.
- The data dictionary uses json-schema-data-dictionary 0.8.0 (from 0.2.0): skip logic followable from either end, an Excel export, and semantic search with a better model. The pages carry the JSON Schema logo.
- The validator is rewritten: row-by-row validation with fast duplicate checks, CSV and TSV read the way QuaC reads them, rules attributed reliably, and each planted toy-data mistake must break exactly one column.
- Run `refresh-assets` in each workspace after updating the skill: it re-copies the website, `serve.py`, and the package's `tools/validate.py`.
